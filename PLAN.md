# Электрощиток: интерактивная карта

QR-код внутри щитка ведёт на сайт. Сайт показывает, что стоит в щитке, что отключает каждый автомат, где в стенах проходят кабели и что делать, если что-то выбило.

## Принципы

- **Работает без света.** Статический сайт и PWA с офлайн-кешем. Когда выбило вводной автомат, роутер и RPi тоже обесточены, а телефон открывает сайт из кеша.
- **Один источник правды.** Всё описание квартиры лежит в `data/panel.yaml`. Из него строятся щиток, план, схема, проверки, наклейки и QR.
- **Доступ только по паролю.** Данные всегда лежат в `public/panel.enc.json`, зашифрованные AES-GCM 256 (ключ через PBKDF2-SHA256, 310k итераций), и расшифровываются в браузере. Пароль можно вшить в QR: `https://…/#/?k=<пароль>`. Фрагмент не уходит на сервер, приложение запоминает ключ и убирает его из адресной строки.
- **Источник правды: зашифрованный файл, а не YAML.** Открытый YAML в публичном репозитории свёл бы шифрование на нет. Демо-YAML в `data/demo.yaml` служит только для начального заполнения (`npm run seed`).
- **Бэкенд не нужен.** Мастер или владелец редактирует всё в браузере. Черновик хранится в IndexedDB. Результат можно скачать (проект `.json`, `.yaml`, зашифрованный `panel.enc.json`) или опубликовать в GitHub-репозиторий через API с личным токеном, который хранится только локально. Публикация запускает деплой Pages.
- **Картинки внутри бандла.** План, фото и документы встраиваются в зашифрованный файл как data URL (изображения сжимаются в WebP до ~1600 px), поэтому они тоже закрыты паролем.

## Состав поставки

| Часть | Где живёт | Что делает |
|---|---|---|
| **Промо-сайт** | GitHub Pages, корень (`/`) | Лендинг: что это, живое демо щитка, как сделать себе, кнопки «Открыть демо» и «Скачать редактор». |
| **Веб-приложение** | GitHub Pages, `/app/` | То, на что ведёт QR в щитке. PWA, работает офлайн. |
| **Десктоп-редактор** | Tauri 2, сборки в GitHub Releases | Тот же Vue-код в нативной оболочке. Мастер открывает и сохраняет файлы `.panel` (зашифрованный бандл) через системные диалоги и передаёт файл владельцу, тот импортирует его в веб или в десктоп. |

Один и тот же код приложения работает в трёх режимах (`VITE_TARGET=web|desktop`). Платформенные операции (открыть файл, сохранить файл) спрятаны за `src/platform/`: в вебе это `<input type=file>` и скачивание, в Tauri: `plugin-dialog` и `plugin-fs`.

## Модель данных (`data/panel.yaml`)

```
meta:        название, адрес (необязательно), дата обновления, контакты (электрик, УК, аварийная служба)
supply:      фазность (1|3), напряжение, разрешённая мощность (кВт), id вводного устройства
panel:       корпус (название), ряды: [{ id, modules, items: [deviceId | {blank: n}] }]
devices:     id (QF1, RCD1…), type, label, rating A, curve B/C/D, poles, width (модули),
             leakage mA, rcdClass AC/A/F/B, brand, model, upstream (id питающего устройства),
             phase (L1/L2/L3), circuit { cable, crossSection мм², lengthM, purpose },
             tags[], notes[{author, date, text}], photos[], docs[]
rooms:       id, name (i18n-словарь или строка), wet: bool, polygon (координаты плана)
points:      id, kind (socket|light|switch|appliance|junction|heating|ac|…), room, x, y,
             device (id автомата), label, powerW, heightMm
routes:      cable runs: device, points[[x,y]…], note (глубина, стена) → слой «не сверлить»
photos:      фото стен до штукатурки: src, room, x, y, caption, date
maintenance: задачи { id, title, intervalDays, devices[] } + журнал { taskId, date, note }
documents:   { title, kind (act|scheme|passport|warranty|other), href }
```

Типы устройств: `mcb` (автомат), `rcd` (УЗО), `rcbo` (дифавтомат), `voltage-relay` (реле напряжения),
`spd` (УЗИП), `meter` (счётчик), `switch` (рубильник), `contactor`, `din-socket`, `bus` (шина N/PE),
`terminal`, `other`.

## Экраны (маршруты)

| Маршрут | Экран | Что там |
|---|---|---|
| `#/` | **Щиток** | Реалистичный щиток с DIN-рейками. Устройства со своим цветом, анимированные рычажки. Тап открывает карточку (на десктопе Sheet справа, на телефоне Drawer снизу). Подсветка цепочки «кто питает / кого питает». Фильтры: тип, комната, тег, «есть замечания». Поиск. |
| `#/d/:id` | Deep link на устройство | Открывает щиток с выбранным устройством (сюда ведут QR на наклейках). |
| `#/plan` | **План квартиры** | SVG-план: комнаты, точки, слои (розетки, свет, техника, кабельные трассы, зоны «не сверлить», фото). Выбор автомата подсвечивает его точки, тап по точке показывает автомат. |
| `#/schema` | **Однолинейная схема** | Дерево, построенное автоматически: ввод → счётчик → реле → УЗО → группы. Анимированный поток тока. |
| `#/find` | **Что отключить?** | Обратный поиск: комната → точка → автомат, с крупной кнопкой «выключи QF7, ряд 2, позиция 5». |
| `#/simulate` | **Симуляция** | Встроена в щиток и план: «выключить» устройство и посмотреть, что погаснет (обесточенные ветки и точки). |
| `#/checks` | **Проверки** | Сечение против номинала, нагрузка на линию, селективность, УЗО во влажных зонах, тип УЗО для инверторной техники, баланс фаз, суммарная мощность против разрешённой. |
| `#/emergency` | **Выбило автомат** | Пошаговый мастер: что выбило (выбор на картинке) → возможные причины → что делать → когда звонить электрику (контакты). |
| `#/maintenance` | **Обслуживание** | Регламент (тест УЗО раз в месяц, протяжка клемм раз в год, проверка УЗИП), журнал, отметки «сделано» (localStorage + экспорт). Просроченные задачи показываются бейджем. |
| `#/photos` | **Фото и документы** | Галерея скрытой проводки с привязкой к плану, документы. |
| `#/labels` | **Наклейки и QR** | Печатная раскладка наклеек под рейку (по модулям 17,5 мм), общий QR на щиток и QR для каждого устройства. CSS для печати. |
| `#/edit` | **Редактор** | Вкладки: *Общее* (адрес, ввод, контакты), *Щиток* (ряды, палитра устройств, перестановка, свойства, питание от), *План* (подложка из PNG/JPG/SVG/PDF или чистый холст с сеткой, рисование комнат-полигонов, расстановка точек, трассы кабелей, маркеры фото), *Фото и документы* (загрузка), *Обслуживание*, *Публикация* (скачать проект/YAML/зашифрованный файл, импорт, публикация в GitHub, смена пароля). Черновик сохраняется автоматически. |
| `#/settings` | **Настройки** | Язык, тема (светлая, тёмная, системная), «забыть пароль», очистка кеша, о данных. |

Общие элементы: верхняя панель (поиск ⌘K, язык, тема), нижняя навигация на телефоне, сайдбар на десктопе, бейдж «офлайн-готово».

## Инженерные проверки (упрощённо, медь, скрытая прокладка)

| Проверка | Правило |
|---|---|
| Сечение и номинал | 1,5 мм² ≤ 10 A · 2,5 ≤ 16 A (20 A предупреждение) · 4 ≤ 25 · 6 ≤ 32 · 10 ≤ 50 · 16 ≤ 63 |
| Нагрузка на линию | I = ΣP·k/U; > 80 % номинала: предупреждение, > 100 %: ошибка |
| Селективность по току | номинал потребителя < номинала питающего (равенство: предупреждение) |
| УЗО и номинал | In(УЗО) ≥ номинала питающего автомата, иначе предупреждение |
| Селективность УЗО | 30 мА после 30 мА: предупреждение (нужно S-тип ≥ 100 мА выше) |
| Влажные зоны | точка во «влажной» комнате без УЗО/дифа ≤ 30 мА: ошибка; > 10 мА для ванной: совет |
| Тип УЗО | стиралка, индукция, инверторный кондиционер на AC-типе: предупреждение (нужен A) |
| Мощность ввода | Σ расчётной нагрузки против разрешённой мощности |
| Баланс фаз | только для 3 фаз: перекос > 30 %: предупреждение |
| Пустые линии | автомат без точек: совет «подписать» |

## Фазы реализации

1. **Каркас.** Vite + Vue + TS, Tailwind v4, shadcn-vue, ESLint, Vitest, роутер, i18n, тема, AppShell.
2. **Домен.** Схема данных, демо-YAML, Vite-плагин, graph, layout, load, checks, lookup, crypto + тесты.
3. **Щиток.** SVG-устройства по типам, рейки, выбор, карточка, фильтры, поиск, подсветка цепочки, анимации.
4. **План.** SVG-план, слои, двусторонняя связь с щитком, симуляция обесточивания.
5. **Схема и проверки.** Однолинейная схема, страница проверок, нагрузка.
6. **Сервисные экраны.** «Что отключить», мастер «выбило», обслуживание, фото и документы.
7. **Печать.** Наклейки и QR.
8. **Редактор.** Черновик, экспорт и импорт YAML, заметки.
9. **Шифрование и PWA.** Экран разблокировки, пароль из QR, офлайн-кеш, манифест, иконки.
10. **Десктоп.** Tauri 2: `src-tauri`, диалоги открытия и сохранения, ассоциация с `.panel`, стартовый экран «Открыть / Создать / Демо».
11. **Промо-сайт.** Отдельная точка входа Vite (`index.html` → лендинг, `app/index.html` → приложение).
12. **Деплой и документация.** GitHub Actions (Pages + опциональный секрет пароля), README: как заполнить свои данные, напечатать QR, развернуть на RPi.
13. **Проверка.** build + test + lint + typecheck, ручной прогон в браузере (телефон и десктоп, светлая и тёмная тема, 4 языка).

## Добавлено по ходу работы

- **Шинные системы (KNX, DALI, Modbus).** Типы устройств: актуатор, блок питания шины, шлюз, модуль входов. У устройства есть физический адрес и каналы с групповыми адресами и точками на плане. Новые типы точек: панель управления и датчик. Экран «Умный дом» с топологией и таблицей групповых адресов. Проверки: нет БП шины, дубли адресов, каналы без нагрузки, групповые адреса без исполнителя. Реле актуатора не считается отключением: «Что отключить?» показывает защитный автомат перед ним. Второе демо `demo-smart.panel`.
- **Слаботочка и гофры.** Трасса бывает силовой, шинной, слаботочной или гофрой. У слаботочной трассы есть состав кабелей (Ethernet, HDMI, антенна и другие) с метками, откуда и куда она идёт. У гофры есть диаметр и признак протяжки. Точка «информационная розетка», экран «Сети и гофры», кликабельные трассы на плане.
- **3D-план** на three.js, загружается лениво. Стены строятся по комнатам с заданной высотой потолка, точки стоят на своей высоте. Трассы идут в полу, по стене на заданной высоте или по потолку, вертикальные опуски к розеткам и щитку достраиваются автоматически.
- **Реальные размеры.** Высота потолков общая и для каждой комнаты отдельно. Слой «Размеры» с длинами стен, площадь и высота у каждой комнаты, длина отрезка при рисовании.
